# Runtime + tooling dependencies for this corpus.
#
# The [mcp] extra installs the MCP SDK that `corpus-mcp-serve` imports. Without it the CLI
# is on PATH but fails at import, so it must be present for the container to serve.
#
# v1.13.0 is a hard floor, and the reason is specific: it is the release that added the
# `performance_report` doc_type (corpus-toolkit#27/#28). `_meta/corpus.yml` declares that
# type, and on anything older EVERY document here fails frontmatter validation because the
# schema does not know the value.
#
# Reusing an existing type was the tempting shortcut and is wrong. An APPR is an agency's
# own claim about its own performance; an `audit_report` is an independent examination of
# that claim. The planned oregon-audits -> oregon-kpm edge exists precisely so an auditor's
# finding can sit beside the measure it disputes, and sharing a type would erase it.
#
# Two precedents: v1.10.0 added `audit_report` for oregon-audits and v1.12.0 added
# `federal_instrument` for federal-reference. A new corpus needing a doc_type release is
# the norm here, not a surprise.
corpus-toolkit[mcp] @ git+https://github.com/OregonAI/corpus-toolkit@v1.13.0
pyyaml

# src/ingest_kpm.py extracts the APPR PDFs (Stage 2). Same extractor oregon-audits and
# oregon-records-retention use, so the page-furniture stripping is shared behaviour rather
# than a third implementation.
#
# NOT pinned exactly here yet. federal-reference pins pypdf==6.14.2 because its
# check_extraction.py compares committed text token-for-token against a re-extraction, and
# pypdf changes extraction between releases. This corpus will want the same discipline once
# Stage 2 commits extracted text — pin it exactly at that point, not before, so the pin
# documents a real constraint instead of a guess.
pypdf
